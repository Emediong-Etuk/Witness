## 1. LLM Insights auto-dispatch (BUILD_PROMPT §7.6)

### 1a. Static analysis of `@smartspectra/node-sdk@3.5.0` (done 2026-11-18)

| Question | Finding | Evidence |
| --- | --- | --- |
| Is there a config field (JS or C ABI) that disables insights? | **No.** The C config struct has `disable_telemetry` but nothing for insights. `reserved0` is always 0. | `js/ffi.js`, `smartspectra_config_t` declaration |
| Does leaving out an `'insight'` listener null the native callback? | **No.** `_ensureSession()` always passes `onInsight`, and `_emit` only drops the event in JS. | `js/smartspectra.js`, `_ensureSession` |
| Does `bindSmartSpectraIpc` register an insight sink? | **Yes, always.** It forwards insights to the renderer port. | `js/main/index.js`, `installCallbacks` |
| Does dispatch depend on breathing **and** cardio both being requested? | Unknown from JS. This is decided in native code. | Pending test (c) |
| Gateway hostname? | Not in `libsmartspectra_capi.so` strings. | Pending egress audit |

**What this means for now:** Witness can't rely on "no listener means no dispatch". Until the empirical tests show otherwise, the consent card must assume that during a session the SDK may send pulse/HRV/breathing **numbers** (never video) to Presage's AI gateway.

## 2. Egress audit (tools/egress-audit)

### Method (fixed before any run)

- **Probe:** `tools/egress-audit/src/probe.ts` runs the **main-process** SDK headless on the default camera, for 180 s per configuration.
  - It never calls `requestInsight`, so every insight it receives was dispatched by the SDK on its own.
  - It stores counts, request ids and byte sizes, never insight text, and never prints the key.
  - It refuses to run without `--i-am-the-subject`.
- **Socket sampler:** every 500 ms it lists the sockets owned by the probe's whole process tree:
  - Linux: `ss -tunpH`, or `lsof` if `ss` is missing;
  - macOS: `lsof -nP -i -a -p`;
  - Windows: `Get-NetTCPConnection`.
  For each remote endpoint it logs the address, port, first and last seen, and the number of samples it appeared in. Remote IPs are then reverse-resolved.
- **Logging proxy (`--proxy`):** a local CONNECT proxy is set in the child's `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY`. It logs the requested **hostname** and port only (never paths, headers or bodies). If the native library ignores proxy variables, the proxy table stays empty and the socket table still shows the traffic.
- **Matrix** (`npm run egress:matrix` prints the exact commands):

| Label | Mode | Telemetry | Insight listener | Purpose |
| --- | --- | --- | --- | --- |
| a-full-telemetry-off-listener-on | full | off | on | §7.6 (a): count unrequested insights |
| b-full-telemetry-off-listener-off | full | off | off | §7.6 (b): hosts present only in (a)? |
| c-quick-telemetry-off-listener-on | quick | off | on | §7.6 (c): no breathing requested |
| d-full-telemetry-on-listener-on | full | on | on | telemetry endpoint(s) |
| e-quick-telemetry-on-listener-on | quick | on | on | telemetry, quick |
| app-full-checkin (`attach`) | full | app default (off) | app | the real Electron app during a check-in |

- **Cost:** 5 × 180 s ≈ 15 credit-minutes, plus one app check-in. It runs only after Greg checks his remaining credits (rule 0.3).
- **Known limits:**
  - Sampling can miss a connection shorter than one interval. The proxy closes that gap only if the library honours it.
  - Reverse DNS returns the IP's own name, often a CDN, which can differ from the requested hostname.
  - OS services acting on the app's behalf aren't counted.
